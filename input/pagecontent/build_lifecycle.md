<!-- PQI Lifecycle | version control of PQI documents, following the ePI approach -->
<p style="color:#374151; font-size:.94em; line-height:1.7; margin-bottom:16px;">Every PQI document goes through a lifecycle: draft, review, approval, post-approval change and, at the end, withdrawal. This page sets out how each version is identified and linked to the one before it, so that sponsors and regulators can trace any document from its first draft to its current approved version. It follows the <a href="https://build.fhir.org/ig/HL7/emedicinal-product-info/en/versions.html" style="color:#2563eb; font-weight:600;">version control approach of the ePI IG</a>, because ePI uses the same FHIR document model.</p>

<div style="background:#eff6ff; border:1px solid #bfdbfe; border-left:4px solid #2563eb; border-radius:8px; padding:14px 18px; margin-bottom:24px;">
  <div style="font-size:.72em; font-weight:700; text-transform:uppercase; letter-spacing:.1em; color:#1d4ed8; margin-bottom:6px;">One document, one history</div>
  <div style="font-size:.88em; color:#1e40af; line-height:1.7; margin:0;">Each of the <a href="build.html#document-granularity" style="color:#1d4ed8; font-weight:600;">20 PQI documents</a> (and each regional document, such as a <a href="build_cpid_ca.html" style="color:#1d4ed8; font-weight:600;">CPID</a>) has its own version history. A post-approval change creates new versions of only the documents it touches; the others keep their current version.</div>
</div>

<p style="color:#6b7280; font-size:.84em; line-height:1.6; margin-bottom:24px;">A <a href="StructureDefinition-Bundle-document-collection-pq.html" style="color:#2563eb; font-weight:600;">document collection</a> is a snapshot of which document versions are sent together. Each collection sent gets its own <code style="font-family:monospace; font-size:.9em; color:#0891b2;">Bundle.identifier</code> and <code style="font-family:monospace; font-size:.9em; color:#0891b2;">timestamp</code>; it does not have a version history of its own.</p>

<h3 id="status" style="font-size:1.35em; font-weight:700; color:#111827; margin-bottom:12px;">Status</h3>
<table style="width:100%; border-collapse:collapse; font-size:.84em; margin-bottom:12px;">
  <thead><tr style="background:#003087; color:#fff;"><th style="padding:9px 12px; border:1px solid #d0d0d0; text-align:left; width:22%;">Composition.status</th><th style="padding:9px 12px; border:1px solid #d0d0d0; text-align:left;">Meaning for a PQI document</th></tr></thead>
  <tbody>
    <tr><td style="padding:9px 12px; border:1px solid #d0d0d0;"><code style="font-family:monospace; font-size:.9em; color:#0891b2;">preliminary</code></td><td style="padding:9px 12px; border:1px solid #d0d0d0;">Draft, sent for review and not yet approved. Blank templates also carry this status.</td></tr>
    <tr style="background:#f9fafb;"><td style="padding:9px 12px; border:1px solid #d0d0d0;"><code style="font-family:monospace; font-size:.9em; color:#0891b2;">final</code></td><td style="padding:9px 12px; border:1px solid #d0d0d0;">Approved by the regulator.</td></tr>
    <tr><td style="padding:9px 12px; border:1px solid #d0d0d0;"><code style="font-family:monospace; font-size:.9em; color:#0891b2;">deprecated</code></td><td style="padding:9px 12px; border:1px solid #d0d0d0;">Superseded, withdrawn or discontinued.</td></tr>
    <tr style="background:#f9fafb;"><td style="padding:9px 12px; border:1px solid #d0d0d0;"><code style="font-family:monospace; font-size:.9em; color:#0891b2;">cancelled</code></td><td style="padding:9px 12px; border:1px solid #d0d0d0;">A draft abandoned before approval, e.g. a withdrawn variation.</td></tr>
    <tr><td style="padding:9px 12px; border:1px solid #d0d0d0;"><code style="font-family:monospace; font-size:.9em; color:#0891b2;">entered-in-error</code></td><td style="padding:9px 12px; border:1px solid #d0d0d0;">Created by mistake; receivers ignore it.</td></tr>
  </tbody>
</table>
<p style="color:#6b7280; font-size:.84em; line-height:1.6; margin-bottom:24px;">The usual path is <code style="font-family:monospace; font-size:.9em; color:#0891b2;">preliminary</code> → <code style="font-family:monospace; font-size:.9em; color:#0891b2;">final</code>. The other three are end states and can be reached from any point.</p>

<h3 id="relatesto" style="font-size:1.35em; font-weight:700; color:#111827; margin-bottom:12px;">Linking versions with relatesTo</h3>
<p style="color:#374151; font-size:.94em; line-height:1.7; margin-bottom:12px;">Each new version points at the version or versions it comes from, with <code style="font-family:monospace; font-size:.85em; color:#0891b2;">Composition.relatesTo.type</code> and <code style="font-family:monospace; font-size:.85em; color:#0891b2;">relatesTo.resourceReference.identifier</code> set to the earlier <code style="font-family:monospace; font-size:.85em; color:#0891b2;">Composition.identifier</code>. Following these links back gives the full history.</p>

<h3 id="steps" style="font-size:1.35em; font-weight:700; color:#111827; margin-bottom:12px;">Step by step</h3>
<ol style="font-size:.88em; color:#374151; line-height:1.8; margin:0 0 24px 0; padding-left:20px;">
  <li><strong>Create a new version.</strong> Keep the document's <code style="font-family:monospace; font-size:.9em; color:#0891b2;">Bundle.identifier</code>. Give the Composition a new <code style="font-family:monospace; font-size:.9em; color:#0891b2;">identifier</code>, increase <code style="font-family:monospace; font-size:.9em; color:#0891b2;">version</code>, set <code style="font-family:monospace; font-size:.9em; color:#0891b2;">status</code> to <code style="font-family:monospace; font-size:.9em; color:#0891b2;">preliminary</code> and point <code style="font-family:monospace; font-size:.9em; color:#0891b2;">relatesTo</code> at the version it comes from.</li>
  <li><strong>Revise during review.</strong> Each revision sent to the regulator is a new version that <code style="font-family:monospace; font-size:.9em; color:#0891b2;">replaces</code> the previous draft. Edits saved on a server between sendings only change <code style="font-family:monospace; font-size:.9em; color:#0891b2;">Bundle.meta.versionId</code>.</li>
  <li><strong>Approve.</strong> The approved version has status <code style="font-family:monospace; font-size:.9em; color:#0891b2;">final</code> and <code style="font-family:monospace; font-size:.9em; color:#0891b2;">replaces</code> the last draft. Changes between versions are shown with the ePI tracked-changes method.</li>
  <li><strong>Send.</strong> Put the new or changed document versions in a document collection. Unchanged documents do not need to be sent again.</li>
</ol>

<h3 id="pqi-rules" style="font-size:1.35em; font-weight:700; color:#111827; margin-bottom:12px;">Rules specific to PQI</h3>
<ul style="font-size:.88em; color:#374151; line-height:1.8; margin:0 0 24px 0; padding-left:20px;">
  <li><strong>Documents are never split or merged.</strong> The 20-document granularity is fixed, so a version history never forks into several documents or joins several into one. Merges in this page are merges of parallel changes to the <em>same</em> document.</li>
  <li><strong>A new version can move up a type.</strong> A 3.2.P.8 at Type 1 can be followed by a version at Type 4. The <code style="font-family:monospace; font-size:.9em; color:#0891b2;">Bundle.identifier</code> stays the same; <code style="font-family:monospace; font-size:.9em; color:#0891b2;">Composition.category</code> shows the new type.</li>
  <li><strong>The same version can go to several markets.</strong> A 3.2.P.3 sent unchanged to several regulators is one version of one document. A market-specific variant, such as a local 3.2.P.1, is a separate document with its own <code style="font-family:monospace; font-size:.9em; color:#0891b2;">Bundle.identifier</code>.</li>
  <li><strong>Shared resources keep their identifiers.</strong> A resource used in several documents (Types 2–4) keeps the same identifier across documents and versions, so a change to it can be traced to every document that uses it.</li>
</ul>
